# WeKnora Data Privacy & Architecture Guide

## Quick Answers

### Q1: Why are only 5 services running when docker-compose.yml has 9 services?
**A:** By design! Docker Compose **profiles** keep optional services disabled until you need them. This saves resources and speeds up startup.

### Q2: Is registration local or does data go outside?
**A:** **100% LOCAL**. All your data stays on your machine. No external data transmission occurs.

## 🏗️ Service Architecture Explained

### Currently Running Services (Default)

These 5 services provide complete RAG functionality:

| Service | Container Name | Purpose | Port | Status |
|---------|---------------|---------|------|--------|
| **frontend** | WeKnora-frontend | Web UI (React/Vue) | 8083 | ✅ Running |
| **app** | WeKnora-app | Backend API (Go) | 8082 | ✅ Running (healthy) |
| **docreader** | WeKnora-docreader | Document parser (Python) | 50051 | ✅ Running (healthy) |
| **postgres** | WeKnora-postgres | Database + Vector storage (pgvector) | Internal | ✅ Running (healthy) |
| **redis** | WeKnora-redis | Task queue manager | Internal | ✅ Running |

### Optional Services (Not Running - Require Explicit Activation)

These services have `profiles:` configuration and only start when explicitly requested:

| Service | Profile | Purpose | When to Enable |
|---------|---------|---------|----------------|
| **minio** | `minio`, `full` | S3-compatible object storage | Alternative to local filesystem storage |
| **jaeger** | `jaeger`, `full` | Distributed tracing UI | Debugging and performance monitoring |
| **neo4j** | `neo4j`, `full` | Graph database | Enable GraphRAG knowledge graph features |
| **qdrant** | `qdrant`, `full` | High-performance vector DB | Large-scale deployments (alternative to PostgreSQL) |

### How to Enable Optional Services

```bash
# Start with MinIO object storage
docker compose --profile minio up -d

# Start with Jaeger for tracing/monitoring
docker compose --profile jaeger up -d

# Start with Neo4j for GraphRAG
docker compose --profile neo4j up -d

# Start with Qdrant for better vector performance
docker compose --profile qdrant up -d

# Start ALL services (includes all optional ones)
docker compose --profile full up -d

# Combine multiple profiles
docker compose --profile jaeger --profile neo4j up -d
```

### Why This Design?

1. **Resource Efficiency**: Only essential services run by default
   - Saves ~2-4GB RAM depending on optional services
   - Reduces CPU usage
   - Faster startup time

2. **Cleaner Port Mapping**: Avoids unnecessary port conflicts

3. **Feature Flexibility**: Enable advanced features only when needed
   - GraphRAG? Add Neo4j profile
   - Large scale? Add Qdrant profile
   - Debugging? Add Jaeger profile

4. **Production Ready**: Your current setup is fully functional for production use

### Your Current Configuration

From your `.env` file:
```bash
STORAGE_TYPE=local           # Using local filesystem (MinIO not needed)
RETRIEVE_DRIVER=postgres     # Using PostgreSQL pgvector (Qdrant not needed)
ENABLE_GRAPH_RAG=false       # Knowledge graph disabled (Neo4j not needed)
# Jaeger tracing not enabled  (Jaeger not needed)
```

**Result**: Minimal, efficient setup with complete functionality! ✅

## 🔒 Data Privacy & Security

#### 1. User Registration & Authentication
```
Browser → Frontend (8083) → Backend API (8082) → PostgreSQL
                                   ↓
                            JWT Token Generated
                                   ↓
```

- ✅ Password hashed with bcrypt (never plaintext)

- ✅ Vectors stored in local PostgreSQL with pgvector extension
- ✅ No OpenAI/Anthropic API calls
- ✅ **Completely offline capable**

```
Your Question → Backend → Retrieve Context → Ollama → Generate Answer
```

### What About That Tracing Warning?

You may see this in logs:
```
traces export: exporter export timeout: rpc error: code = Unavailable desc = name resolver error: produced zero addresses
```

**This is harmless!** Here's why:
- OpenTelemetry tracing is configured to send traces to Jaeger
- Jaeger container is NOT running (it's optional with `--profile jaeger`)
- The app tries to connect to local Jaeger, fails, and continues normally
- **No data goes external** - it's trying to connect to `jaeger:4317` (internal Docker network)

To eliminate the warning:
```bash
# Option 1: Start Jaeger (stays local)
docker compose --profile jaeger up -d

# Option 2: Disable tracing in code (not recommended, warning is harmless)
```

**Docker Compose profiles** keep optional services (MinIO, Jaeger, Neo4j, Qdrant) disabled until you need them. Your current setup is:
- ✅ Fully functional
- ✅ Resource efficient
- ✅ Ready for production use

You have the **minimal viable setup** that provides complete RAG capabilities!

### Is Data Private?
**Absolutely YES!** Your WeKnora installation is:
- ✅ **100% self-hosted** - all services run locally
- ✅ **Zero telemetry** - no tracking or analytics
- ✅ **Air-gap capable** - works completely offline
- ✅ **No cloud sync** - data never leaves your machine
- ✅ **Full privacy** - suitable for confidential documents

The only way data could go external is if YOU explicitly:
1. Add external API keys (OpenAI, Anthropic, etc.)
2. Change storage to cloud providers
3. Use the web search tool in Agent mode

**Bottom Line**: Your registration, documents, conversations, and all data are stored locally on your machine. Nothing is sent to external servers. You have complete privacy and control! 🔒
